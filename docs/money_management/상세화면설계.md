# 돈 관리 탭 상세 화면 설계

> 상태: 설계 초안. 화면과 기능은 아직 구현하지 않았다.
> 아래 날짜·금액·비율과 거래 사례는 화면 설명용 예시이며 실제 사용자 데이터가 아니다.

## 1. 설계 목적과 화면 연결

**돈 관리 탭은 요약 화면으로 두고, 카드를 누르면 그 숫자의 근거를 확인하는 상세 화면으로 연결한다.** 확인 중 잘못 분류된 거래나 반복 일정을 바로 수정해 분석 정확도를 높인다.

요약 화면의 배치는 [화면구성.md](화면구성.md)를 참고한다.

상세 화면은 **5개**로 묶는다. ‘이번 달 예상 지출’과 ‘평소 비교’는 같은 분석 화면의 서로 다른 위치로 연결한다.

| 돈 관리 탭에서 누르는 곳 | 이동 화면 | 핵심 목적 |
| --- | --- | --- |
| 이번 달 예상 지출 카드 | 이번 달 분석 → 예상 지출 영역 | 예상액이 어떻게 계산됐는지 확인 |
| 평소 비교 카드·그래프 | 이번 달 분석 → 평소 비교 영역 | 언제부터 소비가 늘었는지 확인 |
| 다가오는 입출금 → 전체 보기 | 입출금 일정 | 날짜별 예정 수입·출금 확인 |
| 식비·쇼핑 등 항목 카드 | 항목별 상세 | 해당 항목의 소비 원인 확인 |
| 반복 거래 관리 | 정기 거래 관리 | 자동 탐지 결과 확인·수정 |
| 상세 화면 속 개별 거래 | 거래 상세 | 실제 거래 정보와 분류 확인 |

## 2. 이번 달 분석 — 예상액과 비교의 근거

### 배치 순서

1. 월 선택과 **이번 달 예상 지출**
2. `현재까지 실제 소비 + 남은 정기 지출 + 남은 예상 변동지출` 계산 내역
3. 실제·예상·과거 평균을 구분한 누적 그래프
4. 평소보다 증가하거나 감소한 주요 항목
5. `이 예상에 대해 물어보기`

### 상호작용

- ‘남은 정기 지출’을 누르면 해당 금액에 포함된 거래 목록을 펼친다.
- ‘식비 증가’를 누르면 식비의 항목별 상세 화면으로 이동한다.
- 예측 근거에는 **분석 기간과 제외한 일회성 거래**도 표시한다. 사용자가 예상액의 근거를 따라갈 수 있게 한다.

### 계산과 표시

- 실제 소비와 미래 예상액을 구분한다.
- 카드 구매를 소비로 집계했다면 카드대금 출금을 다시 소비로 더하지 않는다.
- 이미 발생한 정기 지출은 남은 정기 지출에 다시 포함하지 않는다. 남은 예상 변동지출에도 정기 지출을 중복 포함하지 않는다.
- 과거 데이터가 부족하면 실제 확보한 기간을 표시하고, 비교 근거가 없으면 평균 비교를 만들어내지 않는다.

## 3. 입출금 일정 — 돈이 움직일 날짜 확인

모바일에서는 **날짜별 목록을 기본**으로 한다.

- 상단: `전체 / 출금 / 입금` 필터
- 중간: 가까운 날짜부터 예정 내역
- 각 내역: 이름, 날짜, 금액, 연결 계좌, `확정 / 추정` 표시
- 하단 또는 상단 버튼: `정기 거래 추가`

### 예정 내역 상세 패널

예정 내역을 누르면 바닥에서 올라오는 상세 패널을 연다.

| 예정 내역 | 패널에서 보여줄 것 | 가능한 행동 |
| --- | --- | --- |
| 카드대금 | 청구액, 결제일, 결제계좌 | 청구 내역 보기 |
| 추정 통신비·구독료 | 예상액, 예상일, 과거 결제 기록 | 이번 예정 수정, 정기 거래 관리 |
| 추정 급여 | 예상 입금일·금액, 추정 근거 | 급여 여부 확인, 예상 정보 수정 |

여기서 날짜를 수정하는 것은 **분석에 쓰는 예정일을 수정하는 것**이다. 실제 통신사 결제일이나 자동이체 설정을 바꾸는 기능과 명확히 구분한다.

## 4. 항목별 상세 — 어디서 소비가 늘었는지 확인

식비 카드를 누른 경우 다음 순서로 구성한다.

1. **현재까지 식비 사용액**
2. 평소 같은 시점 대비 차이와 월말 예상액
3. 최근 3개월과 이번 달 비교
4. 주요 사용처별 합계
5. 해당 월의 개별 거래 목록

예시:

> **식비 20만 원 사용**  
> 평소 같은 시점보다 4만 원 많아.  
> 증가분 중 3만 원은 배달 결제에서 발생했어.

‘배달’처럼 세부 분류가 있는 경우에만 위와 같이 설명한다. 없으면 확인 가능한 가맹점을 기준으로 보여준다. 전체 식비를 파악할 수 없는 경우에는 ‘외식·카페’ 등 실제 분류 범위에 맞는 이름을 사용한다.

- 거래 목록에서 거래를 누르면 공통 거래 상세 화면으로 연결한다.
- **카테고리를 수정하면 합계와 예상액도 함께 갱신**한다.
- 실제 확보된 과거 데이터가 3개월보다 적으면 확보한 기간만 비교한다.

## 5. 정기 거래 관리 — 자동 탐지 결과 확인·수정

상단을 `확인 필요 / 등록됨`으로 나눈다.

### 확인 필요

자동 탐지한 후보와 근거를 보여준다.

> **매달 반복되는 거래 같아**  
> 넷플릭스 · 매월 18일경 · 17,000원  
> 최근 3개월 동안 3회 확인  
> `정기 거래로 등록` · `반복 거래 아님`

위 예시는 실제로 3회 관측했을 때의 표현이다. 한 달치 데이터에 결제가 한 번만 있으면 구독 서비스로 분류할 수 있어도 반복 주기가 확인된 것처럼 표시하지 않는다.

### 등록됨

등록된 항목을 누르면 다음을 확인·수정한다.

| 항목 | 내용 |
| --- | --- |
| 이름·분류 | 통신비, 급여, 월세 등 |
| 주기·예정일 | 매월 15일 등 |
| 금액 | 고정 금액 또는 최근 기록 기반 예상액 |
| 연결된 거래 | 반복 판단에 사용한 실제 거래 |
| 상태 | 예상에 포함 / 제외 |

`이번 달만 건너뛰기`와 `앞으로 예상에서 제외`를 분리한다.

구독료를 예상에서 제외하더라도 **실제 서비스 구독이 해지되는 것은 아니다.** 따라서 버튼 이름을 ‘구독 해지’로 쓰지 않는다.

## 6. 거래 상세 — 분석 근거가 되는 공통 화면

여러 화면에서 재사용하는 하나의 상세 화면이다.

- 거래명, 금액, 일시, 결제 수단·계좌
- 소비 카테고리와 `분류 수정`
- 연결된 정기 거래가 있다면 해당 항목
- `일회성 지출로 표시`

### 분류 수정

- `이번 거래만 변경`과 `이 결제처에 앞으로 적용`을 구분한다.
- 사용자 수정은 분석용 분류에 반영하며 실제 계좌·카드 거래 원본은 바꾸지 않는다.
- 구매 품목을 알 수 없는 거래는 넓은 범주나 미분류로 남길 수 있다.

### 일회성 지출

일회성 지출로 표시해도 **이번 달 실제 소비에는 그대로 포함**한다. 향후 평소 생활비를 추정할 때 제외할 수 있도록 하며, 사용한 돈 자체가 실제 소비 합계에서 사라지지 않게 한다.

## 7. 공통 탐색과 AI 연결

- 화면 이동 시 **선택한 월과 필터를 유지**한다.
- 뒤로 가면 이전 스크롤 위치로 돌아온다.
- AI 패널에 현재 보고 있는 월·항목을 전달한다. 식비 상세에서 ‘왜 늘었지?’를 누르면 같은 맥락으로 질문을 이어간다.
- 실제·확정·추정 금액과 분석 기간을 구분해 표시한다.
- 조회 가능한 거래가 없거나 비교 기간이 부족하면 그 상태를 안내하고 임의의 예상값·평균값을 표시하지 않는다.

## 8. 향후 첫 구현 범위

위 **5개 상세 화면과 예정 내역 패널**을 연결한다.

**분석 → 근거 확인 → 분류·예정 수정 → 분석 갱신**까지 완결된 경험을 제공한다. 이체나 상품 가입은 이 상세 화면 설계의 첫 구현 범위에 포함하지 않는다.

현재 작업에서는 문서와 백엔드 빈 파일만 준비한다. 실제 화면·기능·DB·API는 후속 구현 대상이다.
