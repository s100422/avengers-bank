# 돈 관리 탭 화면 구성

> 상태: 설계 초안. 화면과 기능은 아직 구현하지 않았다.
> 아래 날짜·금액·비율은 화면 설명용 예시이며 실제 사용자 데이터가 아니다.

## 1. 화면의 목적과 탐색 구조

**이번 달 얼마나 쓸까 → 지금 소비 속도는 어떨까 → 앞으로 뭐가 나갈까 → 어디에 많이 썼을까** 순서로 배치한다. 처음 들어왔을 때 핵심을 파악하고, 아래로 내려가면서 이유를 확인하는 구조다.

- 하단 탭: **홈 / 이체 / 돈 관리 / 상품**
- 기존 내 정보: 홈 화면 우측 상단의 프로필 아이콘에서 진입한다.
- 돈 관리 탭: 요약 정보를 보여주고, 각 카드에서 근거를 확인하는 상세 화면으로 연결한다.
- 상세 이동과 동작은 [상세화면설계.md](상세화면설계.md)를 참고한다.

## 2. 위에서부터의 배치 순서

| 순서 | 화면 영역 | 구성 |
| --- | --- | --- |
| ① | 상단 제목·월 선택 | **돈 관리**, `〈 2026년 11월 〉`, 데이터 갱신 시각 |
| ② | 이번 달 예상 지출 | 월말 예상 총액, 현재까지 쓴 금액, 남은 예상 지출 |
| ③ | 평소와 비교 | `평소보다 많음 / 평소 수준 / 평소보다 적음`, 누적 소비 그래프 |
| ④ | 다가오는 입출금 | 급여·월세·통신비·구독료·카드대금의 예정일과 금액 |
| ⑤ | 항목별 소비 | 식비·교통·쇼핑 등 사용액, 평소 대비 차이, 월말 예상 |
| ⑥ | 반복 거래 관리 | 자동 탐지한 거래 확인·수정, 누락된 정기 거래 추가 |

**② 예상 지출과 ③ 평소 비교가 첫 화면의 중심**이다. 모바일에서 이 두 영역을 너무 크게 만들지 않아 스크롤 전에도 이번 달 상태를 파악할 수 있게 한다.

## 3. 이번 달 예상 지출

예상 총액을 가장 크게 보여주고 실제 소비와 남은 예상 지출을 구분한다.

> **이번 달 예상 지출**  
> **148만 원**  
> 현재까지 62만 원 · 남은 예상 지출 86만 원  
> 최근 3개월 월평균 132만 원보다 약 12% 많을 것으로 예상돼.

예상액이 확정 금액으로 보이지 않도록 실제 금액과 예상 금액의 표시를 구분한다.

## 4. 평소와 비교

누적 소비 그래프에는 세 가지 선을 사용한다.

- **실선:** 이번 달 오늘까지 실제 누적 소비
- **점선:** 오늘 이후 월말까지 예상 누적 소비
- **회색 기준선:** 최근 3개월의 평균 누적 소비

그래프 위에는 **“오늘까지 소비는 평소 같은 시점보다 8% 많아”**와 같이 표시한다.

월말 예상 증가율 12%와 현재 증가율 8%는 비교 대상이 다르므로 설명을 붙여 구분한다.

| 지표 | 비교 기준 |
| --- | --- |
| 현재 소비 속도 | 이번 달 오늘까지 실제 소비와 과거 같은 일자까지의 평균 |
| 월말 예상 수준 | 이번 달 예상 총액과 과거 월평균 |

## 5. 다가오는 입출금

가장 가까운 **3건만 먼저 표시**한다.

| 예정일 | 내역 | 금액 | 구분 |
| --- | --- | --- | --- |
| 11월 15일 | 카드대금 | −320,000원 | 확정 청구 |
| 11월 18일 | 통신비 | 약 −65,000원 | 반복 거래 추정 |
| 11월 25일 | 급여 | 약 +2,500,000원 | 반복 거래 추정 |

`전체 일정 보기`를 누르면 입출금 일정 상세 화면에서 이번 달 전체 내역을 확인한다.

**카드대금은 계좌 출금 일정이며, 이미 집계한 카드 소비에 다시 더하지 않는다.** 소비 분석과 현금 입출금 일정을 구분한다.

## 6. 항목별 소비

평소와 차이가 큰 항목부터 보여줘 변화의 원인을 찾기 쉽게 한다.

> **식비 · 평소보다 많음**  
> 오늘까지 20만 원 / 평소 같은 시점 16만 원  
> 이번 달 예상 48만 원  
> `거래내역 보기`

카테고리를 누르면 항목별 상세 화면으로 이동해 거래와 분류를 확인·수정한다. 모든 항목의 개별 거래를 요약 화면에 펼치지는 않는다.

## 7. 반복 거래 관리

반복 거래 관리 영역은 맨 아래에 둔다. 확인이 필요한 후보가 있으면 위쪽에도 작은 안내를 표시한다.

> 확인이 필요한 반복 거래가 2건 있어. `확인하기`

분석 정확도를 높이기 위한 확인 행동을 쉽게 찾을 수 있게 하되, 매번 화면의 중심을 차지하지 않게 한다.

## 8. AI 설명 연결

별도의 큰 채팅창 대신 **요약 카드 아래 한두 문장과 `왜 늘었지?` 버튼**을 배치한다.

탭에서 숫자와 흐름을 바로 확인하고, 이유가 궁금할 때 기존 AI 패널로 이어진다. 현재 선택한 월과 항목을 전달해 같은 맥락에서 설명을 받을 수 있게 한다.

## 9. 데이터와 분류에 따른 표시 원칙

- 최초에는 한 달 정도의 거래를 가맹점 업종·이름으로 넓게 자동 분류하고, 사용자가 직접 지정·수정할 수 있게 한다.
- 구매 품목을 모르는 마트·온라인쇼핑 거래를 식비나 생필품으로 임의 세분화하지 않는다. 애매한 거래는 넓은 범주 또는 미분류로 유지한다.
- 위의 식비 카드는 표시 예시다. 실제 데이터가 외식·카페 결제만 포함한다면 해당 범위를 나타내는 이름을 사용한다.
- 세 달이 쌓이기 전에는 실제 분석 기간을 표시한다. 한 달의 완료된 기록과 비교할 때는 ‘최근 3개월 평균’ 대신 ‘지난달 기준’이라고 표시한다. 비교할 과거 기간이 없으면 비교 데이터 부족을 안내한다.
- 소비 카테고리와 반복 결제 여부는 별도로 관리한다. 구독 서비스의 결제 한 건만으로 반복 주기·금액을 확정하지 않는다.

## 10. 현재 마련하는 백엔드 뼈대

`src/avengers_bank/domains/money_management/`에 다음 빈 파일을 둔다. 아래 역할은 향후 구현 계획이다.

| 파일 | 예정 역할 |
| --- | --- |
| `__init__.py` | 패키지 표시 |
| `router.py` | 화면에서 호출할 API |
| `schemas.py` | 요청·응답 형식 |
| `models.py` | 분류 결과·사용자 규칙·정기 거래 |
| `repository.py` | DB 조회·저장 |
| `service.py` | 분석과 사용자 수정 처리 |
| `classification.py` | 규칙 적용·LLM 거래 분류 |
| `recurring.py` | 반복 거래 후보 탐지 |
| `analytics.py` | 합계·평균·예상 지출 계산 |

원본 거래는 기존 계좌·카드 도메인에서 관리하고, 돈 관리 도메인은 연결된 분석 정보를 관리한다. 현재 단계에서는 API 등록, DB 모델·마이그레이션, 프론트엔드 화면·내비게이션 변경을 구현하지 않는다.
