# 문서 적용 전 확인 사항

## 상태

21개 문서(공통 안내 1, 종류별 약관 5, 개별 상품 15)는 모두 초안이다. 사용자 동의용으로 발행하지 않았으며 임베딩·색인도 실행하지 않았다. Claude가 구현하는 파이프라인에서 검증 후 명시적으로 발행해야 한다. 문서만 추가했으므로 기존 가입 API에는 아직 동의 강제가 없다.

## 코드에서 확인한 차이

| 항목 | 실제 구현 | 문서 처리 |
|---|---|---|
| 입출금 연 금리 | 상품 데이터에 존재하나 이자 지급 로직 없음 | 표시 금리와 지급 미구현을 함께 설명 |
| 예금·적금 금리 | 해지 시 상품 테이블 금리를 읽음 | 가입 당시 금리 보장이라고 쓰지 않음 |
| 적금 납입 예정일/액 | 저장되지만 자동납입·월 정액 검증 없음 | 계획값임을 설명 |
| 청년 적금 | 나이·월 70만 원 누적 한도 검사 없음 | 소개 대상과 미구현 구분 |
| 스타·내맘대로 기간 | 미래 만기일 여부만 확인 | 소개 기간을 강제 조건으로 쓰지 않음 |
| 모바일 특판 | 채널·1년 만기·모집한도 검사 없음 | 미구현 명시 |
| 예금 입금 | 가입 때 가입 금액을 한 번만 입금(개설과 같은 트랜잭션). 가입 후 추가 입금 불가. 입금 실패 시 가입 안 됨 | 가입 후 여러 차례 입금 가능하다고 쓰지 않음 |
| 예금 최소 가입 금액 | 상품 데이터 `min_amount` 검사(정기 10만·스타 100만·모바일 특판 50만 원), 미달 시 BELOW_MIN_AMOUNT | 문서의 최소 금액을 상품 데이터와 일치시킴 |
| 입출금 간 이체 한도 | 1회·1일 검사 | 예적금 납입·카드 결제로 확대 설명하지 않음 |
| 중도해지 | 해지일 < 만기일이면 금리 × 0.5 | 원금 감액과 구별 |
| 만기 후 | 추가 이자·자동해지·자동재예치 없음 | 직접 해지 필요 |
| 신용 청구서 | 종료된 달을 사용자가 생성 | 자동 발행이라고 쓰지 않음 |
| 신용 결제일 | 월말 보정, 공휴일 보정 없음 | 은행 영업일 이연 규칙을 가져오지 않음 |
| 카드 혜택 | 사용처 분류·할인·포인트·환전 없음 | 시드 설명과 실제 처리 구별 |

## 구현 연결 유의점

- DB 상품값과 문서의 예시 수치가 다르면 발행 전 검토가 필요하다. 코드/DB 값을 자동으로 조용히 문서에 덮어쓰지 않는다.
- 약관 버전 보존만으로 과거 가입 금리까지 고정되는 것은 아니다. 이를 개선하려면 별도 상품 조건 스냅샷 설계와 기존 계약 처리 결정이 필요하다.
- 적금 납입 예정액·일자와 카드 결제일은 사용자별 값이다. 문서에 개인 값을 하드코딩하지 말고 소유권이 검증된 조회 도구를 함께 사용한다.
- `manifest.json`의 15개 상품은 현재 시드 기준이다. 존재하지 않는 상품을 로더가 임의 생성하지 말고 오류를 보고한다.
- 문서 집합 밖의 선택 약관이나 마케팅 목적을 새로 만들지 않는다.
- 상품·버전 필터를 먼저 적용한 후 검색한다. 공통 문서는 manifest에 연결된 것만 포함한다.
- 개인 계약 질문에는 가입 시 동의한 버전 집합을 사용한다. 새 가입 질문에는 현재 발행된 집합을 사용한다.
- 구조 검증과 Fake 임베딩 테스트는 외부 API 없이 가능하다. 실제 임베딩 모델·벡터 검색 품질 검증은 Claude 작업 범위다.
