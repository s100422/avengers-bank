## 새 세션에서 이어서 하기

**새 세션에는 이 대화의 기억이 없다.** 이 문서와 `DESIGN_CHANGES.md`가 그 기억을 대신한다. 새 세션에서는 이렇게 시작하면 된다.

> `docs/NEXT_STEPS.md`를 읽고 이어서 진행하자. 아직 ⬜인 항목을 위에서부터 하나씩, 선택지와 추천을 보여 주고 내 답을 받아서 진행해 줘.

특정 항목부터 하고 싶으면 번호를 붙인다. 예: `NEXT_STEPS.md의 1단계 전부 추천대로 진행해 줘`, `2-1부터 해 줘`.

**읽는 순서:** `README.md`(실행 방법) → 이 문서 → `DESIGN_CHANGES.md` 1~3부(무엇이 바뀌었고 무엇이 정해졌나). 특정 항목의 이유가 궁금하면 4부의 C-항목을 본다.

**시작하기 전 준비** (코드를 고치거나 서버·검증 스크립트를 돌릴 때):
- Docker Desktop을 켜고 `docker compose up -d --wait` (DB가 `127.0.0.1:5435`에서 떠야 한다)
- `.env`가 있어야 한다 (`.env.example` 복사). Windows에서는 서버를 `uv run fastapi dev`로 띄운다(`fastapi run`은 안 됨, README 참고)
- 상태 확인: `uv run pytest -q`가 전부 통과해야 한다(지금 131개). `uv run alembic current`가 최신(head)이어야 한다

**작업 규칙** (메모리에도 저장돼 있다):
- 항목 하나를 정하면 구현하고, `DESIGN_CHANGES.md` 4부에 C-항목을 쓰고(부록 B 행 추가, 1·2부 갱신), 3부 "이미 정한 것"에 추가하고, 여기서 상태를 ✅로 바꾼다.

- DB 구조를 바꾸면 마이그레이션 파일을 새로 만든다(`README.md`의 "모델을 바꿨을 때"). 모델을 바꾼 뒤 `scripts/generate_erd_drawio.py`로 ERD v2를 다시 만든다.

## 추천 순서

처음부터 다 할 필요는 없다. **목적이 시연용인지 서비스용인지**에 따라 건너뛴다.

1. **0-1 git** (선택, 하지만 이후 작업의 안전망이 된다)
2. **1단계 전부 확정** — 한 번에 닫는다. 값은 그대로 두고 1-8(type CHECK)만 작업이 있다.
3. **정합성·보안 먼저:** 2-2(DB CHECK) → 2-3(만기 거절) → 2-1(404 통일). 모두 작거나 중간이고, 잘못된 값이나 정보 노출을 막는다.
4. **구조 정리:** 2-6(가맹점명) → 2-5(`outstanding_amount`). 둘 다 마이그레이션이 필요하니 **한 번에 묶어서** 마이그레이션 파일을 하나만 만든다.
5. **기능:** 3-1(적금·예금 해지·출금)을 설계부터. 이게 되면 적금·예금이 의미를 갖는다.
6. **서비스로 쓸 때:** 4단계(4-1 `/health`, 4-4 CORS, 2-11 로그인 제한부터).

나머지(2-4, 2-7 ~ 2-10, 2-12, 2-13, 3-2 ~ 3-9)는 필요가 생길 때 다시 본다.
