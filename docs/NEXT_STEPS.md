특정 항목부터 하고 싶으면 번호를 붙인다. 예: `NEXT_STEPS.md의 1단계 전부 추천대로 진행해 줘`, `2-1부터 해 줘`.

**읽는 순서:** `README.md`(실행 방법) → 이 문서 → `DESIGN_CHANGES.md` 1~3부(무엇이 바뀌었고 무엇이 정해졌나). 특정 항목의 이유가 궁금하면 4부의 C-항목을 본다.

## 6단계: 타행 이체·이체 화면 남은 일 (C-105~C-109)

타행 이체는 운영 허브 등록(은행 코드 903)·서버 배포·보내기/받기 시험까지 끝났다 (2026-11-09). 구성과 운영 방법은 [INTERBANK.md](INTERBANK.md). 남은 일:

1. **정산·대사**(SPEC 10절)와 **본인 명의 계좌 조회**(SPEC 9절): 선택 기능이라 하지 않았다
2. ~~**탈퇴와 PENDING 타행 이체**~~: 탈퇴 사전 조회와 확정 처리에서 미완료 타행 이체를 차단한다(C-112). 실제 PostgreSQL 동시성 검증 결과는 변경 기록을 참고한다.
3. **확인 작업 늦춤**: 30분 뒤에도 30초 간격(SPEC은 10분). 거래가 늘거나 워커를 늘리면 늦춤 규칙과 `SKIP LOCKED`
4. **실제 허브 시험 마무리**: 가짜 은행 902의 `0002~0006` 끝자리 시험과 셀프 시험(`test-receive`)의 동시 중복 시험을 전부 해 보지는 않았다
5. **운영 로그인 인증번호**: 서버에서는 문자 발송기가 `dev`뿐이라 새 기기 로그인·가입 인증번호가 서버 로그에만 남는다. 서버 주소로 직접 접속하는 사람은 인증을 통과할 수 없다 → 실제 문자 발송기 연결이 필요
6. **화면 다듬기**: 계좌 상세 거래내역 필터가 방문마다 초기화됨(C-109), 목록에서 고른 상대는 실명·직접 입력한 상대는 가린 이름으로 보임(C-107), 금액 단계의 'AI 금융 비서' 떠 있는 버튼이 확인 버튼과 겹침, 가입 화면의 `useParams` Suspense 경고
7. **운영 DB 정리**: 시험용 사용자 `hubtest01`·`hubtest02`와 가짜 잔액(시연 전에)
