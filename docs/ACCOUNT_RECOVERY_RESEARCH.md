# 계정 복구 조사 (2026-11-08)

비밀번호 찾기·아이디 찾기를 만들기 전에 **실제 은행과 기준이 어떻게 하는지** 조사한 기록이다. 이 조사를 근거로 "은행형"(계좌 비밀번호 + 휴대폰 인증번호) 복구를 택했다. 구현 기록은 [DESIGN_CHANGES.md](DESIGN_CHANGES.md), 인증 구조는 [AUTH.md](AUTH.md).

> **신뢰도 표시:** 공식 페이지·법령·표준 원문으로 확인한 것은 [확인], 블로그·검색 요약만 근거인 것은 [블로그], 해석은 [해석]. 은행 고객센터 FAQ 상당수가 자바스크립트로 그려지거나 로그인 뒤에 있어 직접 읽지 못한 곳이 있다(신한·농협·인터넷은행 일부). 앱 정책은 자주 바뀌므로 확정 전에 실제 앱에서 다시 확인하는 것이 좋다.

## 한 줄 결론
**이메일 하나만으로 비밀번호를 재설정하는 은행은 찾지 못했고, 국제 기준(NIST)도 이메일을 인증 수단으로 금지한다.** 공통점은 "서로 다른 두 가지로 확인"이다. 국내 은행은 **계좌(계좌번호 + 계좌 비밀번호) + 휴대폰(문자·본인인증) 또는 인증서·OTP**를 쓴다.

## 1. 국내 시중은행
| 은행 | 아이디 찾기 | 로그인 비밀번호 재설정 | 잠김 | 근거 |
|---|---|---|---|---|
| 하나 | 계좌번호 + 계좌 비밀번호 + 생년월일 + (인증서 / 휴대폰 본인인증) | 계좌번호 + 계좌 비밀번호 + 보안매체 + (공동인증서 / ARS). 보안매체가 없으면 앱 간편인증 + 신분증 촬영 + 본인 계좌 확인 | 이용자 비밀번호 5회, 여러 날 누적, 온라인 해제 가능 | [확인] [하나 고객센터](https://kebhana.com/cont/customer/customer01/customer0101/customer010101/index.jsp) |
| 우리 | 생년월일 + 계좌번호 + 계좌 비밀번호 + 휴대폰 번호 → 문자 인증 | "비밀번호 재등록 및 오류해제" 메뉴 존재(절차 미확인) | 확인 못 함 | [확인] [우리 아이디 찾기](https://spot.wooribank.com/pot/Dream?withyou=CQMEM0050) |
| KB | 성명 + 계좌번호 + 계좌 비밀번호 | 같은 화면에서 사용자 암호 설정(세부 미확인) | 계좌 비밀번호 4회 [블로그] | [확인] [KB](https://obank.kbstar.com/quics?page=C055674) |
| 신한 | 메뉴만 확인 | 메뉴만 확인 | 5회 [검색 요약] | 본문 미확인 |
| NH농협 | 확인 못 함 | 확인 못 함 | 보안카드 5회, OTP 10회 | [확인] [농협](https://banking.nonghyup.com/servlet/content/ip/ec/IPEC0001M.thtml) |

- **복구의 기준은 계좌**다. 아이디 찾기와 비밀번호 재설정 모두 계좌번호 + 계좌 비밀번호를 거의 항상 요구한다.
- 여기에 휴대폰·인증서·ARS·OTP 중 하나를 더해 **두 가지**로 확인한다.
- 앱에서는 간편비밀번호·생체인증·자체 인증서가 기본이고 **아이디 로그인은 보조**다(하나 확인, 나머지 [해석]).
- 이메일을 복구에 쓰는 곳은 찾지 못했다.

## 2. 인터넷전문은행·핀테크
| 서비스 | 로그인 | 비밀번호(PIN) 재설정 | 근거 |
|---|---|---|---|
| 토스 | 아이디 없음. 본인 명의 휴대폰 + 비밀번호·생체인증 | 휴대폰 인증 + 계좌 1원 인증 또는 계좌 비밀번호. 계좌가 없으면 신분증 들고 고객센터 | [확인] [토스 보안](https://support.toss.im/security), 재설정은 [블로그] |
| 카카오뱅크 | 앱 비밀번호(6자리) 중심 | 타행 계좌 비밀번호 인증, 실패 시 대체 인증 | [기사](https://news.tf.co.kr/read/economy/2268096.htm) (2025-12-02) |
| 토스뱅크 | 토스 앱 안 | 계좌 비밀번호: 신분증 + 얼굴 인증 | [블로그] |
| 케이뱅크 | 모바일 전용(2023-03 PC뱅킹 중단) | 확인 못 함 | [기사](https://www.metroseoul.co.kr/article/20230227500489) |

- **아이디 개념이 없다.** 휴대폰 + 기기가 계정이라 "아이디 찾기"가 없다.
- 복구는 휴대폰 인증에 계좌 1원 인증·계좌 비밀번호·신분증 얼굴 인증 중 하나를 겹친다.
- 5회 오류 잠금이 관행이고 [블로그], 해제는 본인확인 후 재설정이다. 이메일은 쓰지 않는다.

## 3. 국내 규정
- **전자금융감독규정 제33조(이용자 비밀번호 관리)** [확인, 위키 전재본](https://itwiki.kr/w/전자금융감독규정_제33조)
  - ①항: 비밀번호는 암호화해 보관하고 조회할 수 없게.
  - ②항 1호: 주민등록번호·동일숫자·연속숫자처럼 쉽게 유추되는 비밀번호는 등록 불가.
  - ②항 3호: **"5회 이내의 범위에서 미리 정한 횟수" 이상 틀리면 그 거래를 즉시 중지하고, 본인확인을 거쳐 비밀번호를 다시 부여.** 여러 거래에 공통으로 쓰는 비밀번호는 오류 횟수를 합산.
- **2015-12 금융당국 해석**: 위 본인확인은 대면에 한정되지 않고 비대면 인증기술로도 가능, 방식은 금융회사가 판단. [기사](https://www.dt.co.kr/article/10986311)
- 2015-03 공인인증서 의무 폐지, 2020 전자서명법 개정: 인증 방법을 거래 위험에 맞게 회사가 고른다.
- **이메일만으로 재설정해도 되는지에 대한 명시 규정·해석은 찾지 못했다**(있다고도 없다고도 단정 못 함).

## 4. 국제 기준
- **NIST SP 800-63B Rev.4** [확인](https://pages.nist.gov/800-63-4/sp800-63b.html)
  - 3.1.3.2: "Email SHALL NOT be used for out-of-band authentication". 단 이메일 주소 확인 코드와 복구 코드는 예외.
  - 4.2: 복구 수단은 저장형 복구 코드, 발급형 복구 코드(이메일 24시간·문자 10분, 미리 검증한 주소), 복구 연락인, 신원 재확인. AAL2 계정 복구는 **서로 다른 방법의 코드 2개** 또는 코드 1개 + 기존 인증수단 1개.
  - 4.6: 모든 계정 복구는 **알림을 보내야 한다**(이의 제기 방법 포함).
  - 3.2.2: 연속 실패는 최대 100회까지만 허용(기관이 더 낮게 가능).
  - 3.1.1.2: 단일요소 비밀번호 15자 이상, **구성 규칙 강제 금지**, 주기적 변경 강제 금지.
- **OWASP** [Forgot Password](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html), [Authentication](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html) [확인]
  - 계정이 있든 없든 같은 메시지·상태코드·응답시간.
  - 토큰은 무작위·1회용·만료형·안전 보관.
  - 재설정 후 자동 로그인 금지, 알림, 기존 세션 무효화.
  - 재설정 요청 때문에 계정을 잠그지 말고 요청 횟수를 제한.
  - **잠긴 계정도 복구 절차는 쓸 수 있게**(잠금을 이용한 DoS 방지).
  - 이메일 변경 시 이전 주소로 알림, 새 주소로 확인.
- **해외 은행** [확인]
  - [Wise](https://wise.com/help/articles/2554205/how-can-i-change-or-reset-my-password): 이메일 + 2단계 인증 수단이 둘 다 필요.
  - [Bank of America](https://www.bankofamerica.com/customer-service/contact-us/bank-of-america-login-issues/): 카드·계좌번호 끝 6자리, 문자 코드 10분.
  - [Revolut](https://help.revolut.com/business/help/managing-my-business/profile-and-settings/passcode-password/how-can-i-log-in-with-a-new-mobile-device/): 셀피 + 같은 기기에서 연 이메일.
  - 공통점은 이메일을 쓰더라도 단독으로 쓰지 않는다는 것이다.

## 5. 이 프로젝트의 결정과 근거
| 결정 | 근거 |
|---|---|
| **은행형 복구:** 계좌번호 + 계좌 비밀번호(아는 것) + 휴대폰 인증번호(가진 것) | 국내 시중은행 공통 패턴, NIST의 "두 요소" 취지. PASS·NICE 본인인증은 계약이 필요해 학습 프로젝트에서 불가 |
| **계좌 비밀번호 신설:** 숫자 4자리, 동일·연속 숫자 금지, 5회 잠금, 돈이 나가는 곳 전부 요구 | 국내 은행 관행, 감독규정 제33조 ②항 1·3호 |
| **로그인 잠금을 은행식으로:** 5회 연속 → 잠금 → 비밀번호 찾기로만 해제 (C-089 "느리게"를 대체) | 감독규정 제33조 ②항 3호. 복구 절차로 스스로 풀 수 있어 잠금 DoS 위험이 줄어듦(OWASP) |
| 휴대폰 번호는 가입·변경 때 인증번호로 확인 | 미리 검증한 주소만 복구에 씀(NIST 4.2.2), 번호 바꿔치기 방지 |
| 인증번호: 6자리, 10분, 5회, 1회용, 서버 키를 섞은 해시 저장, 번호당 발송 제한 | NIST(문자 10분), OWASP |
| 응답 동일화, 재설정 후 자동 로그인 금지·모든 세션 폐기·알림 | OWASP, NIST 4.6 |
| 입출금 계좌가 없거나 두 비밀번호를 모두 잊은 경우 → 고객센터 안내(개발용 관리자 명령) | 은행도 이 경우 영업점·신분증 확인 |
| 실제 문자 발송은 나중(지금은 개발용 문자함) | 문자 업체 계약·비용 필요. 발송기만 바꿔 끼우는 구조 |
| **비밀번호 구성 규칙(영문·숫자·특수문자)은 유지** | 국내 은행 관행을 따른다. **NIST Rev.4와는 다르다**(NIST는 조합 강제 금지, 15자 이상 권장)는 점을 기록 |
